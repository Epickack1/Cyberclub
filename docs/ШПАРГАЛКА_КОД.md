# Шпаргалка по коду — что показать / что написать на листочке

К каждому фрагменту — путь, строка, сам код (в том виде, в котором он лежит в репозитории)
и короткий ответ на вопрос «зачем так».

Порядок разделов совпадает с порядком вопросов преподавателя: от архитектуры к деталям.
Всё, что ниже, проверено компиляцией и тестами: **КР1 — 28 тестов, КР2 — 38 тестов, все зелёные.**

## 0. Как отвечать, если спрашивают «покажи весь код»

Не пытаться пересказать всё. Схема ответа всегда одна:

> «Слой такой-то отвечает за то-то. Вот интерфейс — вот реализация. Вот конкретное место,
> где работает правило. Оно покрыто тестом `ИмяТеста`, вот он.»

Три опоры, на которые держится вся защита:

| Опора | Файл | Что доказать |
|---|---|---|
| Слои разделены | `service/`, `repository/` | Сервис не знает про SQL, репозиторий не знает про правила |
| Логика покрыта тестами | `src/test/` | 38 тестов, БД не нужна — репозитории подменены на `Map` |
| Ограничения продублированы | `db/01_schema.sql` | Правило есть и в сервисе, и в БД |

## 1. Архитектура (начинать отсюда)

```
FXML-разметка  →  ui.controller  →  service  →  repository (DAO)  →  JDBC  →  PostgreSQL
                                                ↘ export (стратегия: xlsx / csv)
```

**Что сказать:** «Приложение трёхслойное. `repository` — доступ к данным, весь SQL только там.
`service` — бизнес-правила, не знает ни про SQL, ни про JavaFX. `ui.controller` — только
обработчики событий, тоже без правил. Связывается это вручную в `AppContext`, без Spring.»

Если спросят «а почему не Spring»:

> «Так было в задании КР1 — консольное приложение без фреймворков. Интерфейсы репозиториев
> (`CrudRepository`) как раз заведены с прицелом на КР3: подставляем Spring Data — сервисы
> не меняются. Проверяемость: тесты подменяют репозитории на `InMemory*`, поэтому вся
> логика тестируется без PostgreSQL.»

## 2. Работа с базой данных

### 2.1 Запрос с параметрами — `AbstractJdbcRepository.java:44`

```java
protected <T> List<T> queryList(String sql, ParameterSetter params, RowMapper<T> mapper) {
    try (Connection connection = db.getConnection();
         PreparedStatement statement = connection.prepareStatement(sql)) {
        params.set(statement);
        try (ResultSet rs = statement.executeQuery()) {
            List<T> result = new ArrayList<>();
            while (rs.next()) {
                result.add(mapper.map(rs));
            }
            return result;
        }
    } catch (SQLException e) {
        throw SqlErrorTranslator.translate(e, "выборка данных");
    }
}
```

**Что сказать:** «Три вложенных ресурса закрывает `try-with-resources` — при выходе из блока
закрываются в обратном порядке, даже при исключении. Никаких `finally` с `close()`.
`params` и `mapper` — функциональные интерфейсы, поэтому вызов выглядит как лямбда,
а не как ручное заполнение `ps.setLong(1, …)`. `SQLException` наружу не выпускаем —
переводим в своё исключение, иначе сервисный слой зависел бы от JDBC.»

### 2.2 Два функциональных интерфейса — `AbstractJdbcRepository.java:25-32`

```java
@FunctionalInterface
protected interface ParameterSetter {
    void set(PreparedStatement ps) throws SQLException;
}

@FunctionalInterface
protected interface RowMapper<T> {
    T map(ResultSet rs) throws SQLException;
}
```

**Что сказать:** «Один — как задать параметры, второй — как превратить строку `ResultSet`
в объект. Оба с одним методом, значит реализуются лямбдой. Это убирает повторение
JDBC-кода в каждом репозитории.»

### 2.3 INSERT с возвратом ключа — `AbstractJdbcRepository.java:83`

```java
protected long executeInsert(String sql, ParameterSetter params) {
    try (Connection connection = db.getConnection();
         PreparedStatement statement = connection.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {
        params.set(statement);
        statement.executeUpdate();
        try (ResultSet keys = statement.getGeneratedKeys()) {
            if (keys.next()) {
                return keys.getLong("id");
            }
            throw new DataAccessException("База данных не вернула идентификатор новой записи.");
        }
    } catch (SQLException e) {
        throw SqlErrorTranslator.translate(e, "добавление записи");
    }
}
```

**Что сказать:** «`id` — `BIGSERIAL`, его назначает сама база. Флаг `RETURN_GENERATED_KEYS`
просит вернуть сгенерированный ключ, читаем его через `getGeneratedKeys()`. Клиенту не нужно
ни считать строки, ни гадать следующий `id`.»

### 2.5 Перевод ошибок БД — `SqlErrorTranslator.java:44`

```java
public static AppException translate(SQLException e, String action) {
    String state = e.getSQLState() == null ? "" : e.getSQLState();
    String constraint = constraintName(e);
    String known = constraint == null ? null : CONSTRAINT_MESSAGES.get(constraint);

    if (state.startsWith("08")) {
        return new DataAccessException("Нет соединения с базой данных: " + e.getMessage(), e);
    }
    return switch (state) {
        case "23505" -> new ValidationException(known != null ? known
                : "Нарушение уникальности данных (" + constraint + ").");
        case "23503" -> new BusinessRuleException(known != null ? known
                : "Запись связана с другими данными и не может быть изменена или удалена (" + constraint + ").");
        case "23514" -> new ValidationException(known != null ? known
                : "Нарушено ограничение базы данных (" + constraint + ").");
        case "23P01" -> new BusinessRuleException(known != null ? known
                : "Нарушено ограничение-исключение базы данных (" + constraint + ").");
        case "23502" -> new ValidationException("Обязательное поле не заполнено: " + e.getMessage());
        default -> new DataAccessException("Ошибка выполнения SQL-запроса (" + action + "): " + e.getMessage(), e);
    };
}
```

**Что сказать:** «`SQLException` — техническая ошибка драйвера, пользователю она ничего не
говорит. Смотрим на стандартный код `SQLSTATE`: `23505` — нарушена уникальность,
`23503` — нет клиента или места, `23514` — нарушен `CHECK`, `23P01` — сработало
ограничение-исключение против пересечений, `08…` — нет соединения. Имя ограничения
достаём из `PSQLException` и подставляем человеческий текст из таблицы. Второй уровень
защиты: сервис проверяет правило заранее, БД — страховка на случай обхода.»

### 2.6 Проверка пересечения броней в SQL — `JdbcBookingRepository.java:157`

```java
public List<Booking> findOverlapping(Long stationId, LocalDateTime start, LocalDateTime end, Long excludeBookingId) {
    String sql = SELECT + """
             WHERE b.station_id = ?
               AND b.status <> 'CANCELLED'
               AND b.start_time < ?
               AND b.end_time > ?
               AND b.id <> ?
            """ + ORDER;
    return queryList(sql, ps -> {
        ps.setLong(1, stationId);
        ps.setTimestamp(2, Timestamp.valueOf(end));
        ps.setTimestamp(3, Timestamp.valueOf(start));
        ps.setLong(4, excludeBookingId == null ? -1L : excludeBookingId);
    }, JdbcBookingRepository::mapRow);
}
```

**Что сказать:** «Условие `start_time < :end AND end_time > :start` — это пересечение
полуоткрытых интервалов `[начало, конец)`. Поэтому брони 16:00–18:00 и 18:00–20:00
не считаются конфликтом: место освобождается ровно в 18:00. Отменённые не мешают.
`b.id <> ?` исключает саму себя при редактировании — вместо `IS NULL` подставляем `-1`,
чтобы тип параметра оставался одинаковым. SQL записан текстовым блоком — с Java 15,
читается как обычный многострочный текст.»

## 3. Бизнес-правила

### 3.1 Автоматический статус — `BookingStatus.java:34`

```java
public Set<BookingStatus> allowedTransitions() {
    return switch (this) {
        case CREATED -> EnumSet.of(CONFIRMED, CANCELLED);
        case CONFIRMED -> EnumSet.of(ACTIVE, CANCELLED);
        case ACTIVE -> EnumSet.of(COMPLETED);
        case COMPLETED, CANCELLED -> EnumSet.noneOf(BookingStatus.class);
    };
}

public boolean canTransitionTo(BookingStatus next) {
    return next != null && allowedTransitions().contains(next);
}
```

**Что сказать:** «Конечный автомат задан прямо в перечислении — `switch`-выражением Java 21,
а не цепочкой `if`. Диаграмма состояний рисуется ровно по этому коду. `EnumSet` вместо
`Set.of` — потому что элементы принадлежат самому перечислению.
Переход проверяется в одном месте, и этот же набор использует диалог смены статуса:
пользователю показываются только разрешённые варианты.»

### 3.2 Пересечение интервалов — `Booking.java:48`


**Что сказать:** «Классика интервальной алгебмы: два интервала `[a, b)` и `[c, d)`

### 3.3 Расчёт стоимости — `BookingService.java:254`

```java
public BigDecimal calculatePrice(Station station, LocalDateTime start, LocalDateTime end) {
    long minutes = Duration.between(start, end).toMinutes();
    long halfHours = (minutes + 29) / 30;
    return station.getHourlyRate()
            .multiply(BigDecimal.valueOf(halfHours))
            .divide(BigDecimal.valueOf(2), 2, RoundingMode.HALF_UP);
}
```

**Что сказать:** «Тариф часовой, а платим за получасовые интервалы с округлением вверх:
100 минут — это два получаса, не полтора. Округление вверх через целочисленное деление
`(minutes + 29) / 30` — без вещественных чисел, без `Math.ceil`, без ошибок округления.
`BigDecimal` — потому что деньги нельзя считать в `double`. Делим на 2, чтобы перевести
рубли-в-час в рубли-за-полчаса, `HALF_UP` — округление копеек. Проверено тестом
`priceRoundsUpToHalfHour`: 90 минут → 225 руб., 4 часа VIP → 1200 руб.»

### 3.4 Ночное время — `BookingService.java:338`

```java

        return true;
    }
    // начало днём: ночь начнётся в ближайшие 22:00 — попадает ли этот момент внутрь интервала
```

**Что сказать:** «Ночь — интервал, который переходит через полночь, 22:00–06:00, поэтому

проверить, попадает ли этот момент внутрь брони. Логика чистая, и она отдельно

### 4.1 Фильтр как предикат — `BookingFilter.java:39`

```java
public Predicate<Booking> toPredicate() {
    if (from != null && to != null && to.isBefore(from)) {
        throw new ValidationException("period", "Конец периода раньше его начала.");
    }
    List<String> words = words(text);
    return booking -> matchesText(booking, words)
            && (status == null || booking.getStatus() == status)
            && (stationType == null || booking.getStationType() == stationType)
            && (clientId == null || clientId.equals(booking.getClientId()))
            && (from == null || !booking.getStartTime().toLocalDate().isBefore(from))
            && (to == null || !booking.getStartTime().toLocalDate().isAfter(to));

```

**Что сказать:** «Фильтр — это `record` из значений формы, который умеет превратить себя
в `Predicate<Booking>`. Критерий, который не задан, выключается проверкой `== null` —
поэтому один и тот же предикат покрывает и «ничего не выбрано», и полный набор фильтров.
Обратите внимание: сервис возвращает `java.util.function.Predicate` — обычный интерфейс JDK,
в нём нет ни одного упоминания JavaFX. Поэтому сервисный слой ничего не знает про
интерфейс, а `FilteredList` просто принимает этот предикат.»

### 4.2 Поиск по нескольким словам — `BookingFilter.java`

```java
private static boolean matchesText(Booking booking, List<String> words) {
    if (words.isEmpty()) {
        return true;
    }
    String haystack = String.join("\n",
            "#" + booking.getId(),
            nullToEmpty(booking.getClientNickname()),
            nullToEmpty(booking.getClientFullName()),
            nullToEmpty(booking.getStationName()),
            nullToEmpty(booking.getComment())).toLowerCase(Locale.ROOT);
    return words.stream().allMatch(word -> word.startsWith("#")
            ? String.valueOf(booking.getId()).equals(word.substring(1))
            : haystack.contains(word));
}
```

**Что сказать:** «Собираем всё, по чему ищем, в одну строку-«сено». Пустой запрос — сразу
«да», иначе `allMatch` по пустому списку и вернул бы то же, но проверка читается яснее.
Каждое слово запроса должно найтись — `allMatch`, поэтому `shadow vip` работает как «и».
Слово с решёткой отбрасываем и сравниваем с номером **числом**, а не подстрокой:
иначе `#12` нашлось бы в брони №120. `Locale.ROOT` приводит к регистронезависимому
сравнению — на другой локали системы результат не изменится.»

### 4.3 Компараторы внутри перечисления — `BookingSortField.java:13`

```java
public enum BookingSortField {
    START_TIME("По времени начала", Comparator.comparing(Booking::getStartTime)),
    PRICE("По стоимости", Comparator.comparing(Booking::getTotalPrice)),
    STATUS("По статусу", Comparator.comparing(Booking::getStatus)),
    CLIENT("По нику клиента", Comparator.comparing(Booking::getClientNickname, String.CASE_INSENSITIVE_ORDER)),
    DURATION("По длительности", Comparator.comparing(Booking::getDuration));

    private final Comparator<Booking> comparator;

    BookingSortField(Comparator<Booking> comparator) {
        this.comparator = comparator;
    }

    /** Компаратор с учётом направления; при равенстве ключей — по ID. */
    public Comparator<Booking> comparator(boolean ascending) {
        Comparator<Booking> base = ascending ? comparator : comparator.reversed();
        return base.thenComparing(Booking::getId);
    }
}
```

**Что сказать:** «Каждая константа перечисления хранит свой компаратор. Список всех полей
сортировки строится через `values()` — добавил константу, она сама появилась в интерфейсе.
`String.CASE_INSENSITIVE_ORDER` — чтобы «shadow» и «Shadow» стояли рядом. По возрастанию
и по убыванию — один и тот же компаратор, убывание это `reversed()`, без дублирования кода.
`thenComparing(getId)` — правило разрешения ничьих: если у двух броней совпали ключи,
порядок не должен «прыгать» при каждой перерисовке. `getDuration()` уже возвращает
`Duration`, а тот сравнивается сам, приводить к минутам не нужно.»

## 5. JavaFX: запуск и потоки

### 5.1 Фоновая загрузка из БД — `FxTasks.java:18`

```java
public static <T> void run(Callable<T> work, Consumer<T> onSuccess, Consumer<Throwable> onError) {
    Task<T> task = new Task<>() {
        @Override
        protected T call() throws Exception {
            return work.call();
        }
    };
    task.setOnSucceeded(event -> onSuccess.accept(task.getValue()));
    task.setOnFailed(event -> onError.accept(task.getException()));
    Thread thread = new Thread(task, "cyberclub-db");
    thread.setDaemon(true);
    thread.start();
}
```

**Что сказать:** «JDBC блокирует поток. Если читать базу в потоке интерфейса, окно замерзает
и перестаёт отвечать. Поэтому запрос уходит в отдельный поток, а `setOnSucceeded`
и `setOnFailed` выполняются уже в потоке JavaFX — там и можно трогать элементы интерфейса.
Поток демонный, чтобы программа могла закрыться, не дожидаясь запроса.»

### 5.3 Валидация в форме — `FormController.java:66`

```java
public final Optional<R> trySubmit() {
    clearErrors();
    try {
        return Optional.ofNullable(submit());
    } catch (ValidationException e) {
        Control field = e.getField() == null ? null : fields.get(e.getField());
        if (field != null) {
            field.getStyleClass().add(ERROR_CLASS);
            field.requestFocus();
        }
        showError(e.getMessage());
    } catch (AppException e) {
        showError(e.getMessage());
    } catch (RuntimeException e) {
        showError(Dialogs.friendly(e));
    }
    return Optional.empty();
}
```

**Что сказать:** «Три уровня обработки. `ValidationException` несёт ключ поля — по нему
находим нужный элемент, подсвечиваем и ставим в фокус. Остальные исключения приложения
показываем текстом. Всё непредвиденное — через `friendly`, которая поднимается по цепочке
причин и наружу отдаёт понятный текст, а в журнал пишет стек-трейс. Пользователь
никогда не видит стек-трейс. Возвращается `Optional`: пусто означает «не сохранилось»,
и окно остаётся открытым.»

### 5.4 Почему при ошибке форма не закрывается — `FormDialog.java`

```java
saveButton.addEventFilter(ActionEvent.ACTION, event ->
        form.trySubmit().ifPresentOrElse(result::set, event::consume));
```

**Что сказать:** «Это фильтр события, а не обработчик. Фильтр срабатывает **до** того,
как диалог закроется. При ошибке вызывается `event.consume()` — событие погашено,
диалог остаётся открытым, пользователь видит подсвеченное поле и текст.
Если всё сошлось — `result::set` подставляет результат и окно закрывается штатно.»

## 6. Экспорт

### 6.1 Выбор реализации по расширению — `ExportService.java`

```java
public int export(List<Booking> bookings, Path file) {
    if (file == null) {
        throw new ValidationException("Файл для сохранения не выбран.");
    }
    if (bookings.isEmpty()) {
        throw new ValidationException("Нет данных для экспорта: таблица пуста (проверьте фильтры).");
    }
    Exporter exporter = exporterFor(file);
    exporter.export(new ExportData(List.copyOf(bookings), statisticsService.forBookings(bookings)), file);
    return bookings.size();
}
```

**Что сказать:** «Формат не выбирают вручную в коде — его определяет расширение файла,
которое выбрал пользователь в диалоге (`exporterFor`). Добавить PDF или JSON — значит
дописать класс и добавить его в список; существующий код не меняется. Это паттерн
«стратегия». Пустую выборку экспортировать бессмысленно — поэтому проверка до записи,
с понятным сообщением.»

### 6.2 Экранирование CSV — `CsvExporter.java:72`

```java
static String escape(String value) {
    if (value == null || value.isEmpty()) {
        return "";
    }
    boolean quote = value.indexOf(';') >= 0 || value.indexOf('"') >= 0
            || value.indexOf('\n') >= 0 || value.indexOf('\r') >= 0;
    return quote ? '"' + value.replace("\"", "\"\"") + '"' : value;
}
```

**Что сказать:** «Кавычки ставим только когда они действительно нужны — значение с
разделителем `;`, кавычкой или переносом строки. Внутри кавычки удваиваются, как
требует RFC 4180. Разделитель `;` — потому что у нас русская локаль и Excel по умолчанию
не так разделяет. И отдельно пишется BOM `﻿`, иначе Excel откроет файл
в кодировке ANSI и покажет вместо русских букв кракозябры.»

## 7. База данных

### 7.1 Запрет двойной брони на уровне БД — `db/01_schema.sql:68`

```sql
CONSTRAINT excl_bookings_overlap EXCLUDE USING gist (
    station_id WITH =,
    tsrange(start_time, end_time) WITH &&
) WHERE (status <> 'CANCELLED')
```

**Что сказать:** «Это защита от гонки: два запроса одновременно проверяют, что место
свободно, оба видят, что свободно, и оба вставляют. На уровне приложения от этого
не спастись. Здесь база сравнивает диапазоны времени: одинаковое место — и пересекающиеся
интервалы — значит нарушение, вставка отклоняется. `tsrange` по умолчанию полуоткрытый
`[)`, ровно как у нас в логике, поэтому смежные брони не конфликтуют. `WHERE` исключает
отменённые — они место не занимают. Требуется расширение `btree_gist` — оно включается
в начале скрипта.»

### 7.2 Связи таблиц

```sql
CONSTRAINT fk_bookings_client  FOREIGN KEY (client_id)  REFERENCES clients(id)  ON DELETE RESTRICT,
CONSTRAINT fk_bookings_station FOREIGN KEY (station_id) REFERENCES stations(id) ON DELETE RESTRICT,
```

**Что сказать:** «Связи настоящие, не «просто поле». `ON DELETE RESTRICT` запрещает удалить
клиента, на которого ссылаются брони. Согласованность обеспечивает база, а не код.»

## 8. Тестируемость — частый вопрос

**Как вы проверяете логику, если нужна база?**

> «Сервисы написаны против интерфейсов `ClientRepository`, `StationRepository`,
> `BookingRepository`. В тестах они подменены на `InMemoryClientRepository`,
> `InMemoryStationRepository`, `InMemoryBookingRepository` — обычные `LinkedHashMap`
> с тем же интерфейсом. Поэтому 38 тестов проходят без PostgreSQL, за секунды.»

**Как тестировать логику, завязанную на время?**

```java
public BookingService(BookingRepository bookingRepository, ClientRepository clientRepository,
                      StationRepository stationRepository) {
    this(bookingRepository, clientRepository, stationRepository, Clock.systemDefaultZone());
}

public BookingService(BookingRepository bookingRepository, ClientRepository clientRepository,
                      StationRepository stationRepository, Clock clock) {
    this.bookingRepository = bookingRepository;
    this.clientRepository = clientRepository;
    this.stationRepository = stationRepository;
    this.clock = clock;
}
```

> «Время не берётся из `LocalDateTime.now()` напрямую, а через `java.time.Clock`.
> В тесте подставляется `Clock.fixed(...)» — «сейчас» становится константой,
> и проверка «нельзя бронировать в прошлом» становится детерминированной,
> а не зависит от того, в какой минуте запустили тест.»

**Что покрыто тестами:** `BookingServiceTest` — 14 тестов на все правила брони,
`ClientServiceTest` — 7, `BookingFilterTest` — 6, `BookingStatusTest` — 5,
`ExportServiceTest` — 4 (реальные файлы во временной папке), `StationServiceTest` — 2.

Проверить: `cd KR2-JavaFX && ./mvnw test` → `Tests run: 38, Failures: 0, Errors: 0`.

## 9. Частые каверзные вопросы (короткие ответы)

**Чем `record` отличается от обычного класса?**
> «Класс с неизменяемыми полями; компилятор сам делает конструктор, геттеры, `equals`,
> `hashCode`, `toString`. Использую, когда это просто набор значений: `BookingFilter`,
> `Statistics`, `ExportData`, `DatabaseConfig`.

**Зачем `Optional`?**
> «Чтобы «может не быть результата» было в сигнатуре, а не в `null` по всей цепочке.
> `findById` возвращает `Optional` — вызывающий обязан это учесть.

**Что такое `EnumSet`?**
> «Реализация `Set` именно для перечислений: хранит элементы в битовой маске `long`,
> поэтому для enum с числом констант до 64 память — одна восьмибайтовая переменная
> и операции очень быстрые.

**Почему `BigDecimal`, а не `double`?**
> «`double` хранит число приблизительно, и накопление ошибки даёт расхождения в копейках.
> `BigDecimal` — десятичный, деление задаётся точностью и режимом округления.

**Что даёт `try-with-resources`?**
> «Гарантированное закрытие в обратном порядке, в том числе при исключении.
> Ресурсы объявляются в том же блоке, где используются, — их нельзя забыть закрыть.»

**`Statement` или `PreparedStatement`?**
> «Только `PreparedStatement`. Значения передаются отдельно от текста запроса и
> не сращиваются со строкой — SQL-инъекция невозможна. Бонусом база может переиспользовать
> план выполнения. `Statement` в проекте не используется нигде, кроме получения
> сгенерированных ключей как флага.

**Как вы тестируете, что интерфейсы не «протекают»?**
> «Компилятор: сервисы принимают `BookingRepository`, а не `JdbcBookingRepository`.
> Если бы в сервисе появилась ссылка на JDBC-класс, подмена в тестах перестала бы
> работать и тесты бы не собрались.»
